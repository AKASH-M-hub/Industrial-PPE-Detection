3. Technical Challenges Faced & Engineering Solutions (Part I) Root-Cause Analysis

Issue 1: Hugging Face ZeroGPU Server Port Conflict & 405 Method Not Allowed Resolved
Symptom: API requests from the frontend to /api/v1/detect and /api/v1/reason repeatedly failed with HTTP 405 Method Not Allowed, or the Hugging Face container hung upon initialization.
Root Cause: The environment attempted to launch a secondary background uvicorn.run() instance on the same default port (7860) already claimed by Hugging Face's supervisor process. This caused internal port binding collisions where Gradio's internal reverse proxy intercepted raw POST requests and rejected them.
Engineering Fix: Mounted the FastAPI ASGI router directly into the Gradio app lifecycle using gr.mount_gradio_app(app, demo, path="/") and executed a single unified demo.launch(server_name="0.0.0.0", server_port=7860). This allowed both the interactive Gradio UI and headless REST endpoints to cleanly share port 7860.
Issue 2: Hugging Face Git Pre-Receive Hook Rejection on Binary Model Weights Resolved
Symptom: Executing git push space main was rejected by Hugging Face remote with pre-receive errors: "File weights/rtdetr_ppe_best.pt is 66.2 MB; this exceeds GitHub / Hugging Face 10MB quota without Git LFS / xet".
Root Cause: Tracking binary model weights directly within Git history caused repository bloat and violated remote space push constraints.
Engineering Fix: Added weights/*.pt and *.pdf to .gitignore, uploaded the trained weights to a dedicated public Hugging Face Model Hub (Akashhhhwqx/rtdetr-workplace-ppe-detection), and built an automatic lazy-downloader into src/detector/model.py that transparently fetches the 66.2 MB file into memory/cache on first startup.
Issue 3: ZeroGPU CUDA Dynamic Memory Allocation & Worker Thread Timeouts Resolved
Symptom: RT-DETR tensor execution initially threw CUDA device mismatch errors or timed out when called concurrently from external REST clients.
Root Cause: Hugging Face ZeroGPU dynamically allocates Nvidia A100/H100 slices only when functions are wrapped with @spaces.GPU. Raw FastAPI background threads bypassed this lifecycle and fell back to CPU mode, causing severe latency spikes (from 28ms to >4.5s).
Engineering Fix: Wrapped inference routes with @spaces.GPU(duration=60) and implemented a robust fallback mock class for non-ZeroGPU local environments, ensuring seamless runtime portability across both local CPU and cloud GPU.

3. Technical Challenges Faced & Engineering Solutions (Part II) Production Hardening

Issue 4: Cross-Origin Resource Sharing (CORS) & Dual Payload Ingestion Resolved
Symptom: The frontend application hosted on Vercel was blocked from calling the backend Hugging Face Space by browser CORS preflight security policies (No 'Access-Control-Allow-Origin' header).
Root Cause: Cross-domain requests between vercel.app and hf.space required explicit CORS preflight negotiation and handling of both standard multipart FormData and JSON base64 payloads.
Engineering Fix: Configured FastAPI CORSMiddleware with allow_origins=["*"], allow_methods=["*"], and allow_headers=["*"]. Enhanced /api/v1/detect and /api/v1/reason to auto-detect content-type and seamlessly parse both multipart image uploads and raw base64 data URIs.
Issue 5: Real-World Sensor Glare, Rain Blur, & Distant Scale Hallucinations Resolved
Symptom: Out-of-focus job-site security cameras and rain-streaked lenses caused standard detectors to hallucinate PPE compliance or miss distant workers whose heads occupied <20×20px (<0.05% of frame).
Root Cause: High-frequency detail loss in blurred imagery prevents transformer queries from resolving helmet curvature boundaries, causing ambiguous predictions.
Engineering Fix: Engineered a Laplacian focus variance check (σ² = Var(∇²I)). If σ² < 60.0, the pipeline halts and outputs an explicit refusal: "status": "insufficient_information", eliminating false safety certifications in degraded conditions.
Issue 6: Zero-Framework Constraint Enforcement vs. Agentic Library Bloat Resolved
Symptom: Standard LLM orchestration tools (LangChain, CrewAI, AutoGen) introduce heavy dependency overhead, slow cold-starts, and unpredictable non-deterministic execution paths.
Root Cause: The screening specification strictly prohibited external agentic frameworks in favor of hand-written, auditable logic.
Engineering Fix: Built a 100% hand-written deterministic Intent Router using compiled regex token classifiers (\bhelmet\b, \bvest\b). Non-visual questions bypass the vision model entirely, saving 41ms of GPU compute while maintaining pure Python auditable flow.
